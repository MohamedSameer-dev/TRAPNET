3. mmWave Radar — Deep Explanation

What is mmWave?

Millimeter Wave radio signals (1mm–10mm wavelength), operating at 24GHz–77GHz. Your project uses the HLK-LD2410 (24GHz) — costs ₹400–450 and fits on a fingernail.

How FMCW Works (The Core Trick)

FMCW = Frequency Modulated Continuous Wave. The radar transmits a "chirp" — a signal whose frequency sweeps linearly from 24.000 GHz to 24.250 GHz in ~1 millisecond. When this bounces off a human and returns, the returned signal is slightly behind in frequency. That frequency gap = distance to the human.

What It Measures

ParameterHow It's Measured
DistanceFrequency difference between transmitted vs received chirp
Speed (velocity)Doppler shift — moving person compresses/stretches the wave
Angle/DirectionPhase difference between multiple antennas (MIMO)

The Key Ability — Stationary Human Detection

A thief who freezes motionless — PIR misses them, camera in dark misses them. But even a stationary person is breathing. Chest moves ~5mm per breath. The LD2410 detects that 5mm chest movement as a Doppler micro-signature. So even a hidden, frozen intruder is detected.

LD2410 UART Output to ESP32

Target State: MOVING / STATIONARY / NO TARGET
Movement Distance: 2.4 meters
Movement Energy: 87 (0–100 confidence)
Static Distance: 2.4 meters
Static Energy: 72

Honest Limitations

  • Cannot identify WHO the person is — presence only, no face/identity
  • Large animals (dogs/cats) can trigger it
  • Walls weaken the signal — thick brick/RCC blocks it
  • LD2410 gives one zone output — not per-person tracking
False triggers from fans/AC airflow — fix by setting energy threshold > 40 before triggering lockdown.

4. CCTV Integration — Using Your Existing Camera

I have a CCTV camera with battery and SD card storage. How to integrate it?
Depends on camera type. Three scenarios covered below.

Scenario 1 — IP Camera (WiFi or LAN port)

Easiest path. Access live feed via RTSP URL: rtsp://192.168.1.64:554/stream. Raspberry Pi runs OpenCV on the stream for tamper detection and YOLOv8 person tracking.

Scenario 2 — Analog CCTV (coaxial cable)

Use EasyCap USB video capture card (₹300–400) to convert analog signal to USB → Raspberry Pi reads it as a normal video feed in OpenCV.

Scenario 3 — USB Camera / Webcam

Simplest: plug directly into Raspberry Pi USB port. OpenCV reads it as cv2.VideoCapture(0).

Your Camera's Built-in Battery — Project Value

Camera stays alive if thief cuts mains power. Combined with 18650 backup on ESP32 side, the entire system survives power cut — this is a genuine IEEE-worthy resilience feature.

Your Camera's Built-in SD Card — Project Value

Two independent storage layers: Camera SD (continuous loop recording) + Raspberry Pi SD (event-triggered snapshots). Even if ESP32/Pi is destroyed, camera footage survives.

5. Camera Tamper & Offline Resilience

Problem: What if thief sprays paint on camera?

Implemented in OpenCV software: continuously compare average frame brightness. If brightness suddenly drops to near-zero → treat it as intrusion trigger, not failure. Spraying the camera activates lockdown.

Problem: What if camera is physically smashed?

Radar doesn't have a lens. You can't spray it. It's a PCB with antennas. Even if camera is completely destroyed, radar still detects breathing, solenoid still locks, GSM still sends SMS.

Two-Layer Redundancy Design

AttackWhat TRAPNET Does
Spray paint on cameraSudden darkness = tamper flag = lockdown triggered
Cloth over cameraUniform frame = tamper flag
Camera smashedRadar is sole detector — full response continues
WiFi cut / jammedGSM + SD card take over — physical actions unaffected
Mains power cut18650 battery backup keeps system alive 4–6 hours

6. SOS Alert System — Like Disaster Management

I want the SOS to not work through any app or other things. It should work like the disaster management message — an alert sound in a 10–15 metre radius from the robbery place. No app, no internet.
Three simultaneous layers using only your existing ESP32.

Layer 1 — WiFi Beacon SSID Broadcast

ESP32 uses esp_wifi_80211_tx to inject 802.11 beacon frames. Every phone within 15–30 metres sees the network name instantly in their WiFi list — no app, no pairing, no internet.

All nearby phones see in WiFi list:
🚨 ROBBERY ALERT - CALL 100
🚨 TRAPNET ALERT - SHOP 4
🚨 INTRUDER DETECTED

Open source: GitHub — spacehuhn/esp32_beaconSpam using esp_wifi_80211_tx

Layer 2 — BLE Eddystone URL Beacon

ESP32 BLE stack broadcasts Eddystone-URL beacon pointing to a local emergency page. Chrome (Android) and Safari (iOS) show an automatic notification banner — no app required. 10–15 metre radius.

Layer 3 — GSM SMS via SIM800L

Sends SMS to owner's number and police number via cellular network. Works with zero WiFi. Unlimited range. Also sends GPS coordinates if the asset (cash box) is moved.

7. Through-Wall Radar — Honest Assessment

Can I add UWB through-wall radar within ₹15,000 budget? I told my professor it's the main point.
Honest answer with three critical problems.

Real Price of TI IWR1443BOOST (77GHz Radar)

SourcePrice
DigiKey (import to India)~$299 USD = ₹25,000+
AliExpress (clone)~$85 USD = ₹7,100
Indian distributors (Mouser/Arrow)₹22,000–₹28,000

Three Critical Problems Beyond Cost

  1. Needs a PC to process data — outputs raw ADC point cloud over LVDS/USB. ESP32 cannot handle this data.
  2. Deep learning required on top — just having the board doesn't give you through-wall detection. Needs months of dataset collection + model training.
  3. 77GHz is WORSE for walls — Higher frequency = worse wall penetration. True through-wall radar uses lower frequency UWB (3–10GHz), not 77GHz. IWR1443 is the wrong hardware entirely.

What to Tell Your Professor

"Sir, through-wall radar requires UWB (3–10GHz) hardware costing ₹40,000+ with dedicated DSP processing — outside student project feasibility. Instead, our system achieves equivalent security coverage through strategic multi-point sensor placement: LD2410 radar nodes at each room entry point eliminate the need for through-wall detection entirely, while providing superior detection reliability within the covered zone."
Drop through-wall claim. Replace with "multi-point perimeter coverage using sensor fusion" — more accurate, more achievable, more impressive to knowledgeable examiners.
