Principle 1: Provide Full Hardware Context

Never ask generic questions like "How to code ESP32 serial?". Instead, specify exact chip models, pin maps, baud rates, and library dependencies.

// GOOD AI PROMPT: "I am using ESP32 WROOM-32 with HLK-LD2410C on GPIO16(RX2) and GPIO17(TX2) at 256000 baud using HardwareSerial(2). Write a non-blocking FreeRTOS task on Core 0 to parse radar target energy."
🗺️

Principle 2: Request Plans Before Code Execution

Use Planning Mode to evaluate edge cases, memory budgets, and potential pin conflicts before writing production firmware.

// GOOD AI PROMPT: "Create a technical implementation plan for interfacing ESP32 USB-OTG Serial to an Android Foreground Service. Include baud rate selection, buffer sizing, and phone sleep prevention."
🔍

Principle 3: Root-Cause Debugging Over Symptom Patching

When a compilation error or runtime crash occurs, paste the raw un-truncated compiler stack trace instead of asking for random code rewrites.

⚡

Principle 4: Empirical Verification Strategy

Always test generated code on actual hardware or simulation step-by-step. Verify voltage levels with a multimeter or logic analyzer before connecting load relays.

🚩 4-Step Engineering Success Roadmap

  • Step 1 — Hardware Validation: Test each sensor individually on ESP32 (mmWave UART, IR interrupt, Relay trigger, SIM800L AT commands) before combining code.
  • Step 2 — Mobile Model Export & Benchmark: Export YOLOv8n to TFLite INT8 format. Measure frame time on your smartphone using Android Studio Profiler (aim for < 15ms).
  • Step 3 — Serial Protocol Integration: Establish USB-OTG or BLE link between ESP32 and Smartphone. Validate packet checksums and data integrity.
  • Step 4 — Full Multi-Modal Stress Test: Trigger radar and IR sensors simultaneously while monitoring phone CPU temperature, latency, and automated cloud alert delivery.
